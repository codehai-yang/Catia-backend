## getglb 接口改造：把「零件实例名」写进 glTF 节点名

需求：前端要按零件实例名在数模上高亮 CATIA 选中项，后端必须给出唯一标识。

**改之前的坑（关键发现）**：`app/utils/step_to_gltf.py` 旧实现把所有叶子零件合并成一个
`TopoDS_Compound`、再整体 `AddShape` 一次，所以生成的 GLB 里只有一个节点、且没有名字，
前端根本无法定位到单个零件去做高亮。这不是加个字段的事，必须改导出结构。

### 改动内容

- `app/utils/step_to_gltf.py`（重写）
  - 每个零件 `shape_tool.AddShape(shape, False)` 成为一个独立 XDE 标签（= 一个 glTF 节点）。
  - `TDataStd_Name.Set(label, 实例名)` 写节点名；writer 设
    `SetNodeNameFormat(RWMesh_NameFormat_InstanceOrProduct)`。
  - `step_to_gltf()` 新增 `name` 参数；`steps_to_gltf()` 的 entries 兼容 2 元组 / 3 元组
    `(step_path, matrix, name)`，旧的二元组调用不破。
  - 顺带修复：原来的 `sys.exit(1)` 改为 `raise RuntimeError`（在 FastAPI 线程池里抛 SystemExit 很危险）。
- `app/services/catia/service.py`
  - 新增 `CatiaService._instance_name(product, index)`：取 `Product.name`，取不到时兜底 `part_<i>`。
  - `_export_instances_to_glb` / `_export_reference_to_glb` 把实例名透传给导出层。
- 接口签名与响应格式**不变**（仍返回二进制 GLB）。唯一标识 = glTF `node.name` = CATIA 实例名，
  与 `/getselected` 返回的 `parts[].name` 同源（都是 `Product.Name`），前端可直接对齐。

### 验证

`_verify_named_glb.py` 端到端跑通：3 个 STEP → GLB 里 3 个命名节点 + 3 个 mesh，
scene roots = [0,1,2]，旧 2 元组调用退化为 `part_0`/`part_1`。
`app/utils/step_to_gltf.py` 与 `app/services/catia/service.py` 均编译 + 导入通过。

### 环境

运行/验证用 `F:\office\conda\envs\catia310\python.exe`（OCC、pycatia、win32com 都在这）；
项目根目录的 `.venv` 里没有 OCC。

## 追加：分支级导出问题调查（"选单个分支却返回整根线束"）

用户反馈：CATIA 里选单个分支（树里或 3D 视图），前端总是显示整根线束。

### 已定位的根因

`get_glb` 走的是 `ref_doc.ExportData(stp)` —— **整文档导出**。而一个「多分支」线束的
**所有分支几何都在同一个 CATPart 里**（见 MEMORY.md 的模型结构），所以选任何分支都导出整个
`MultiBranchable1.CATPart`。

### 探测结论（用真实 CATIA 会话，cable example.CATProduct）

- `SelectedElement.LeafProduct` 只给到最深的 **Product**（`多分支1.1`），不是最深几何体。
- 树里的 `分支.N` 是 ELW 特征，**未暴露给自动化**：`Value` / `Reference` 一律解析为 `多分支1.1`；
  `Search("Name=分支*,all")` 能找到 4 个，但同样无法区分。
- `Reference.DisplayName` 只能给出 product 级路径。
- `Selection.Copy` + 新建零件 + `PasteSpecial("CATPrtResultWithOutPartLink")` **不可用**
  （剪贴板空 → 导出空白 3126 字节 STEP）；副作用：会话里留下 `ccp_dummy10~12_Format_*` 占位文档。
- 零件疑似可视化模式：`Search("Name=肋*,all")` 返回 0。

### 新增的临时脚本（都在项目根，后续可删）

`_diag_selection.py` / `_diag_export.py` / `_diag_part_tree.py` / `_diag_branch.py`
`_test_body_export.py` / `_check_session.py` / `_sample_selection.py`（选择变化采样器）

### 待办

等用户在真实会话里点击「分支.2」与 3D 视图中的分支，用 `_sample_selection.py` 采样结果
判断是否还存在可用的区分途径（如 3D 拾取点 `GetCoordinates` 做空间匹配）。

## 追加：分支级导出已实现（几何判定 + 拾取点）

采样结果（用户真实点击）给出了明确答案，据此完成了改造。

### 决定性事实

1. **树里点 `分支.N` → 拿不到分支号。** 采样期间该次点击没有产生任何新状态；
   配合之前 `Search("Name=分支*,all")` 的 4 个命中全部是
   `Type=Product / Value.Name=多分支1.1 / PartNumber=多分支1 / Products=0 /
   Ref.DisplayName=cable example/.../几何束1.1/多分支1.1/`，
   且 `几何束1.1` 下只有 1 个子节点 —— 确认 `分支.N` 是 CATPart 内部电气特征，
   自动化接口**完全不可见**。这是 CATIA 硬限制，不是代码 bug。
2. **3D 视图点分支 → 能拿到分支号。** 选中项 `Value.Name` /
   `Reference.Name` 形如
   `Selection_RSur:(Face:(Brp:(EhiBundleSegmentRib.2;0:(Brp:(ElecCurve.2;1);
   Brp:(GSMCircle.2;...))));...)`，里面的 `2` 就是分支号。
3. **STEP 里的实体顺序 = 分支顺序。** 整体导出的 STEP 含 4 个
   `MANIFEST_SOLID_BREP`，名字是 `几何体.1..4`（`\X2\51E04F554F53\X0\` = 几何体）。
   用真实拾取点验证：点 Rib.2 → 到第 2 个实体距离 **0.0000**，到其它 ≥75；
   点 Rib.1 → 到第 1 个实体 **0.0000**，到其它 ≥51。**顺序与分支号严格一致**。
4. `read_step_file_with_names_colors` 拿到了名字但只有 `多分支1` 一层
   （XDE 不把 4 个实体当命名节点），所以名字走不通 → 改用**几何判定**。

### 改动内容

- `app/utils/step_to_gltf.py`
  - 新增 `StepEntry` dataclass（`step_path/matrix/name/branches/pick_points`），
    `_as_entry()` 兼容旧的 2/3 元组调用（不破现有调用方）。
  - 新增 `_iter_top_solids()` / `_distance_to_point()`（`BRepExtrema_DistShapeShape`）/
    `_merge_solids()` / `select_branch_geometry()`。
  - **裁剪优先级**：拾取点几何判定 > 分支序号；都不可用时保留整个零件（并 warning）。
  - 先应用实例矩阵、再判距离，这样总成坐标系的拾取点才能直接比较。
  - `step_to_gltf(..., branches=, pick_points=)`、`steps_to_gltf(..., branches=, pick_points=)`
    新增可选参数（函数级默认值 + entry 级覆盖）。**节点名仍是实例名，契约不变。**
- `app/services/catia/service.py`
  - `_BRANCH_NAME_PATTERN = re.compile(r"(?:EhiBundleSegmentRib|ElecCurve|GSMCircle)\.(\d+)")`
  - `_branch_index(item)`：从 `Value.Name` / `Reference.Name` 解析分支号。
  - `_pick_point(item)`：`SelectedElement(item).get_coordinates()`；`Type=="Product"` 或
    `(0,0,0)` 视为无效（非几何选择的兜底值）。
  - `_branch_selection(selection, count, leaf_name)`：只收集**与目标叶子零件同名**的选中项，
    多选时取并集 → 支持"选中 2~3 个断开的分支"。
  - `get_glb()` 返回 4 元组 `(bytes, filename, parts, branches)`；两个 `_export_*` 同步改签名，
    且**只把裁剪信息给被选中的那个实例**（多实例时避免误裁）。
- `app/schemas/catia.py`：`GlbPayload` 新增 `branches: list[int] = []`（空 = 整零件导出）。
- `app/api/v1/endpoints/catia.py`：解包 4 元组并透传 `branches`。
